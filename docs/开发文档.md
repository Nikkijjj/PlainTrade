# 一、数据 Pipeline

> **详细内容（接口参数、返回格式、字段映射、坑、恢复步骤）见

## 1.1 全景图

```
┌─ 触发层 ────────────────────────────────────────────────┐
│ ① build_db    一次性铺历史底座（D2），之后冻结             │
│ ② refresh     增量更新，TTL 驱动（live 模式请求前自动调）   │
│ ③ scripts     手动补数据 / 探测接口 / 补正文 / 裁窗口       │
└───────────────────────┬─────────────────────────────────┘
                        ↓ 幂等写入（REPLACE / IGNORE / upsert）
┌─ 事实层：data_files/plantrade.db（SQLite 单文件）─────────┐
│ prices_daily · index_daily · announcements · financials   │
│ boards · board_daily · board_members · news · docs_fts    │
└───────────────────────┬─────────────────────────────────┘
                        ↓ 只读打开 + as-of 封死（data/db.py）
┌─ 工具层：tools/（6 个工具，JSON Schema + 超时 + 失败降级）┐
└───────────────────────┬─────────────────────────────────┘
                        ↓
                   agents/（研究层）
```

**核心原则：agent 永不碰网络、不写 SQL。** 它只能通过 `tools/` 拿数据，`tools/` 只通过 `data/db.py` 读库。

## 1.4 数据缺口的影响边界（**不阻塞开发**）

库里还有三处没补：公告正文、板块、新闻。**它们都不阻塞 B/C 开工**，影响面很窄：

| 缺口 | 现状 | ✅ 不影响 | ⚠️ 影响 |
|---|---|---|---|
| **公告正文** | 0 / 2,816 条 | 链路跑通、agent 逻辑、界面渲染 | `Evidence.quote` 只能是标题 → `adapt.fidelity.judge()` 判定偏宽松（没原文可对照） |
| **板块** | 0 行 | 个股场景全部、agent 链路 | `market_event` 的"哪些板块在跌"柱状图没数据 |
| **新闻** | 0 条 | 全部（回放不用它） | 事件场景只讲指数与板块；`MODE=live` 时会自动抓 |

三条要说清的：

**① 公告分析师"能用但浅"，不是不能用。**
它仍能拿到 10 条标题，里面含"年度报告 / 减持 / 回购 / 分红"这类关键信息，够产出 `type=fact` 的 claim。
只是 `evidence.quote` 只能填标题，所以保真度判定会偏宽松。

**② 板块为空时，`chart.plan` 必须降级为 `skip`。**
`db.board_pct_changes()` 在 `board_daily` 为空时返回 `[]`。
如果照样出图，就会画一张**空柱状图** —— 和"乱画"同级的视觉失真。
要求：`reason="板块数据不可用"`，`decision=skip`。

**③ 新闻为空不是缺陷。**
新闻接口只能回溯约 40 天，**进历史证据链就是前视偏差**。回放模式为空是正确行为。

### 什么时候必须先补齐

| 时间点 | 必须补 | 为什么 |
|---|---|---|
| 做 `market_event` 端到端演示之前 | **板块** | 事件场景的核心就是"板块普跌"的解释和图 |
| 评估指标定稿之前 | **正文 >70%** | 「失真率」要拿通俗表述和**原文**对照 |

其余时间，数据缺口对开发**没有影响**。

## 1.5 五条数据规则（违反则整个评估作废）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | as-of 只认 `publish_time` / `announce_date`，**绝不用 `ingested_at`** | 后者是入库时间，用它等于偷看未来，且不会报错 |
| 2 | **同日公告次日才可见**（`publish_time = 当日 23:59:59`） | 公告只到日精度 |
| 3 | 财务按**实际披露日**截断，且**首次披露优先**（`OR IGNORE`） | 重述行会覆盖原始披露 |
| 4 | 展示用 **qfq**；算收益 hfq/qfq 等价；**绝不用 hfq 显示价格** | 平安银行 hfq=1737 而真实价 12 元 |
| 5 | 业务代码**只走 `data/db.py`**，不写裸 SQL | 漏写 as_of 不会报错，锁进函数才能被单测覆盖 |

## 1.6 实时 vs 历史

| | 回放 replay（评估） | 实时 live（demo） |
|---|---|---|
| `as_of` | 历史日期 `"2025-01-04"` | 当前时刻 `"2026-11-23 15:30:00"` |
| 联网 | ❌ 只读快照 | ✅ 按 TTL 增量拉 |
| 结果 | 重跑完全一致 | 每次可能更新 |

TTL：新闻 5 分钟 / 公告 1 小时 / 行情 12 小时 / 财务 24 小时。命中 TTL 后 0.66 秒返回且不联网。

⚠️ **铁律**：`eval/runners/batch.py` 必须 `assert settings.mode == "replay"`，
否则评估时顺手跑 live 就把新数据写进库，**测试集泄漏**。

## 1.7 一次请求的完整时序

```
run(user_text, as_of)
 ① new_run_id()
 ② if mode == "live": refresh.ensure_fresh([...])    ← 唯一碰网络的地方
 ③ router.route(text, as_of)                          ← as_of 在此固定，之后只传不重取
 ④ tools.call(get_announcements / get_series / ...)   ← 全部带同一个 as_of
 ⑤ agents: 三分析师 → 辩论 → 经理 → ArgDoc
 ⑥ adapt: summarize → termgate → fidelity → chart → guardrail
 ⑦ span 落盘 logs/spans.jsonl
```

## 1.8 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 接口返回 0 条但 HTTP 200 | 缺参数（如新闻的 `req_trace`）或反爬 | 比对 `data/sources/em_*.py` 参数；看 `data_files/raw/` 原始响应 |
| `RemoteDisconnected` / 502 | **IP 限流**（不是代码错） | 停，冷却 30–60 分钟；见 数据状态.md §7 |
| `asof_financials` 返回 `{}` | 该日之前没有已披露财报 | 查 `financials.announce_date` |
| PE 异常大/小 | 用 hfq 价格算市值 | 确认取 `adj='qfq'` |
| 多词检索命中不到 | 没装 jieba，走 2-gram 降级 | `pip install jieba` |

# 二、Agent 搭建

## 2.1 分层与依赖（15 个顶层目录）

| 目录 | 职责 | 禁止 |
|---|---|---|
| `contracts/` | **唯一契约**，零依赖 | import 任何业务模块 |
| `config/` | 配置 + 13 个提示词 + 图表契约 + 术语表 | 写逻辑 |
| `tools/` | agent 访问外部世界的**唯一边界** | 自己发 HTTP / 写 SQL |
| `data/` | 取数、建库、`db.py` 唯一取数入口 | import agents/adapt/pipeline |
| `research/` | FTS5 检索 | 访问网络 |
| `llm/` | 模型调用、结构化输出、缓存、计费 | 写提示词 |
| `observability/` | run_id + span | import 业务模块 |
| `memory/` | 短期对话状态 | 存用户资产信息 |
| `agents/` | 研究层（**讨论型**：多轮、有状态） | 出现 `if task == ...` 分支 |
| `adapt/` | 适配层（**变换型**：纯函数、可单测） | 读写数据库/文件 |
| `guardrails/` | 越界检测与拒答 | 内联进 agent |
| `pipeline/` | 编排，**唯一知道"三个入口"的地方** | 写业务逻辑 |
| `ui/` | 渲染（薄） | 做任何判断 |
| `eval/` | 指标与批量跑 | 写进主流程 |
| `scripts/` | 一次性工具 + 自检 | 被主流程引用 |

## 2.2 五个契约（D2 冻结，跨模块只传这几个）

```python
ArgDoc        # 研究层产物：claims + evidence + stance + confidence + explanation_status
ChartSpec     # 图表决策：要不要出图 / 哪种 / 为什么（不含任何数值）
PlainBrief    # 最终产物：UI 只渲染它
AgentMessage  # agent 间通信：claim 只能引用 evidence_used 里的证据
ToolSpec / ToolCall / ToolResult   # 工具层：JSON Schema + 超时 + ok/error
```

**契约里已经带了硬校验**（不是文档写写）：

```python
ChartSpec(decision="emit", need_type="no_attribution", chart_type="line")
# → ValueError: need_type=no_attribution 时必须 decision=skip

ArgDoc(as_of="2025-01-04", evidence=[Evidence(publish_time="2025-03-20", ...)])
# → ValueError: 证据晚于 as_of，属未来信息
```

## 2.3 工具层规范

```python
# tools/registry.py 已实现
register(ToolSpec(name=..., params_schema={JSON Schema}, returns=..., timeout_s=...), fn)
call(ToolCall(name, args)) → ToolResult(ok, data, error, elapsed_ms)
```

**硬规则**：
- 失败返回 `ok=False`，**不抛异常**（让 agent 能自我修正）
- 每个工具声明 `timeout_s`
- agent **不许直接 import `data/`**，只能走 `tools/`

已注册 6 个：`get_series` / `get_trade_dates` / `get_announcements` / `search_docs` / `get_financials` / `get_recent_news`

## 2.4 研究层：三个分析师 + 辩论 + 经理

| 模块 | 输入 | 输出 | 硬约束 |
|---|---|---|---|
| `router.py` | 用户问题 | `{task, code, as_of, is_panic}` | 全系统唯一做"这是哪类问题"的地方 |
| `analysts/disclosure.py` | 公告列表 | `claims`（**只 fact**） | 禁止推断；无证据输出空数组 |
| `analysts/fundamental.py` | 财务指标 | `claims`（**只 inference**） | 不许自己算数字 |
| `analysts/technical.py` | 指标（代码算好的） | `claims` | **禁止给支撑位/买入点**（越界红线） |
| `debate.py` | claims + evidence_ids | Bull/Bear 反驳 | **不得引入新事实**，只能引用已有 evidence_id |
| `manager.py` | claims + 辩论 | **ArgDoc** | **唯一有权输出 stance**；证据不足必须 `no_view` |

`BaseAgent` 已经写好，子类只实现两个方法：

```python
class DisclosureAnalyst(BaseAgent):
    name, prompt_name, schema = ..., "analyst_disclosure", _Payload
    def build_vars(self, ctx) -> dict: ...      # 把 ctx 变成 prompt 变量
    def parse(self, payload, ctx) -> list[Claim]: ...   # 结构化输出 → claims
```

基类自动做了三件事：从 `config/prompts/` 读提示词、走 `complete_json` 做修复重试、**丢弃引用不存在证据的 claim**（`drop_hallucinated`）。

## 2.5 适配层：7 个纯函数（C 的主战场）

| 模块 | 作用 | 关键映射 |
|---|---|---|
| `summarize.py` | 结论压缩 | 置信度 4 档：≥0.70 比较有把握 / 0.55–0.70 **大概六成** / 0.45–0.55 说不出高下 / **<0.45 弃权** |
| `termgate.py` | 术语门控 | 检测行话 → 挂解释卡 → 复检 → 重写（≤3 轮） |
| `fidelity.py` | 保真度判定 | `supported / weakened / distorted` |
| `chart.py` | 图表决策 | 归因不明 → **强制 skip** |
| `render.py` | 确定性渲染 | 数据由代码填，LLM 不碰数值 |
| `attribution.py` | 三层归因 | 事实 / 相关信号 / 我们不知道 |
| `guardrails/escalation.py` | 越界拦截 | 词表 + 正则双层，两轮不过 → 拒答 |

**为什么适配层必须和 agents 分开**：它是纯函数，**可以单测**（给输入比输出）。混进 agent 之后，所有验证都得跑完整链路，vibe coding 时根本没法测。

## 2.6 编排：三个问题模板 + node 降级

`pipeline/tasks.py` 定义三个模板（入口只是模板，共用一条管线）：

```python
TASKS = {
  "market_event":        需要 index+news，不要财务，
  "stock_outlook":       需要 prices+financials+announcements,
  "allocation_literacy": 不用库,
}
```

`pipeline/graph.py` 声明每个 node 的超时与降级：

| node | 超时 | 失败怎么办 |
|---|---|---|
| router | 5s | 按页面提示兜底 |
| fetch | 30s | abort |
| analysts | 60s | **skip**（写入 `information_gaps`） |
| debate | 20s | **skip**（经理直接汇总） |
| manager | 30s | abort |
| chart | 10s | **default = 不出图** |
| guardrail | 5s | **default = 拒答** |

**越界拦截失败默认拒答** —— 宁可不出，不可越界。

## 2.7 LLM 规范

| 规则 | 做法 |
|---|---|
| 提示词是数据 | 全部在 `config/prompts/*.md`（13 个），代码里只出现文件名 |
| 每个提示词有契约头 | `<!-- 输入：… 输出：… 约束：… -->`，改提示词不碰代码 |
| 结构化输出 | 必须走 `llm/structured.complete_json(schema, repair_attempts=1)`，**禁止裸 `json.loads`** |
| 缓存 | `key = sha256(task|code|as_of|prompt_hash|model)` |
| 成本 | `llm/cost.py` 按 token 记账，写进 span |
| 温度 | `llm_temperature = 0`（可复现） |

# 三、可视化设计

## 3.1 三条设计原则

**① 图表是回答的组成部分，不是页面的一部分。**
没有"图表区"，只有"这次回答要不要配图"。由 `ChartPlanner` 在生成时决定。

**② agent 决定，不由界面预设。**
`ChartSpec` 是决策对象：`decision(emit|skip)` + `need_type` + `caption` + `reason`。

**③ 不出图也是一种输出——而且是本项目的记忆点。**

> 归因不明时，画一条走势线出来，会让用户以为"已经知道原因"了。
> 所以说实话 + 不画图，比画一张好看的图更有价值。

## 3.2 六类图表契约（`config/chart_contracts.yaml`）

| 需求类型 | 触发条件 | 图表 | 必需元素 | 禁止 |
|---|---|---|---|---|
| `trend` | 结论依赖 ≥20 日变化 | 单序列折线 | 时间轴、单位、"历史不代表未来" | 截断 y 轴、双轴 |
| `compare` | 个股 vs 指数/同业 | 归一化相对收益（=100） | 基准线、图例 | 双 y 轴 |
| `risk` | 结论含风险判断 | 回撤填色曲线 | 最大回撤标注 + 发生日期 | 只给收益不给回撤 |
| `allocation` | 钱怎么放 | 堆叠条形 | "示例非建议"水印 | 真实标的 + 比例 |
| `attribution` | 事件解读 | 板块涨跌幅柱状 | 板块标签、跌幅数值 | 趋势线、预测 |
| **`no_attribution`** | `explanation_status = unknown` | **不出图** | — | **任何图表** |

最后一行有**代码级强制**：`ChartSpec` 的 validator 会直接抛异常。

## 3.3 职责划分：LLM 只选型，不画图

```python
# agent 输出的是这个（不含任何数值）
ChartSpec(
    decision="emit", need_type="risk", chart_type="drawdown_curve",
    data_ref="series.close.hfq",
    caption="过去一年它最多跌过 28%——这不是危言耸听，是真实发生过的。",
    reason="结论涉及回撤已经很深，需要让用户看到过程而非单点跌幅",

```

```

```

**LLM 接触不到任何数字** → 从机制上排除"图里的数字是编的"。

## 3.4 视觉规范

| 项 | 规范 | 理由 |
|---|---|---|
| 涨跌颜色 | **涨红跌绿**（A 股习惯） | 反了会让用户瞬间误解 |
| 每张图必带 caption | 一句话说"这张图想让你看到什么" | 没 caption 的图只是装饰，不可评估 |
| 免责标注 | "历史不代表未来" / "示例非建议" | 强制 |
| 字体 | 图表内中文用系统字体，避免方框 | — |
| 不靠颜色单独表达 | 加文字标注（色盲友好） | — |

### 3.4.1 术语标注：虚线下划线 + 点击解释卡

回答里出现金融术语时（市盈率、回撤、换手率…），**不能只靠上下文猜**，要能就地看解释。

| 项 | 规范 | 理由 |
|---|---|---|
| 标注样式 | **虚线下划线**（`border-bottom: 1.5px dotted`），字号与颜色**不变** | 实线/变色会打断阅读；虚线是"这里可以点"的通行约定 |
| 触发方式 | **点击**（不是 hover） | 移动端没有 hover；hover 提示还容易一闪而过看不见 |
| 弹出内容 | 小卡片 `term` / `plain`（一句话说明）/ `analogy`（打个比方） | 类比是给零基础用户的第二道保险 |
| 数据来源 | `PlainBrief.glossary[]`，前端按 `term` 做文本匹配包一层 `<span data-id>` | **不许让 LLM 直接输出 HTML**，否则等于把渲染权交给模型 |
| 关闭方式 | 点卡片外部 / 按 Esc / 再点该词 | 三项都要支持，否则手机上关不掉 |
| 键盘可达 | `tabindex="0"` + Enter 打开 | 无障碍 |
| 卡片边界 | 只说"这个词是什么意思"，**不得夹带结论或建议** | 解释卡也是输出，一样受越界约束 |

**不做**：
- ❌ 替换掉术语（"把市盈率改成贵不贵"）—— 会丢失精确性，属于失真
- ❌ 整段加下划线（只能标术语本身）
- ❌ 用原生 `title` 属性充当解释卡 —— 移动端点击不触发，且无法排版

> 原型已有雏形：`frontend/index.html` 里 `withGlossary()` + `abbr` 样式。
> 现状是原生 tooltip，**需按本节升级为点击弹卡**。这一条挂在 D-12。

## 3.5 界面形态：**对话式**（不是卡片页）

```
┌──────────────────────────────────────┐
│ PlainTrade              [新对话]      │
├──────────────────────────────────────┤
│                    今天科技股跌这么多？ │  ← 用户气泡右对齐
│ ◆ PlainTrade                          │
│ 跌的不是你那一只。创业板指跌 5.2%…     │  ← 回答：段落
│ ┌────────────────────────┐            │
│ │  （板块跌幅柱状图）      │            │  ← 图表嵌在回答里
│ └────────────────────────┘            │
│ 6 个板块全在跌，说明不是某个行业的问题 │  ← caption
│ ▸ 3 条依据                            │  ← 折叠，不占版面
├──────────────────────────────────────┤
│ [今天跌了多少] [600519] [10 万怎么分]  │  ← 示例问题
│ ┌────────────────────────┐  [↑]      │
│ │ 问点什么…               │            │
│ └────────────────────────┘            │
│ AI 生成内容可能有误，不构成投资建议     │  ← 全界面唯一免责，一行
└──────────────────────────────────────┘
```

**只有这些元素**：顶部、对话流、输入区、一行小字、调试页（`?debug=1`）。
**不做**：开屏强制弹层、固定免责底栏、"你不该做的事"独立面板。
