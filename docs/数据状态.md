## 二、七个接口详解

### 2.1 日线 / 指数 —— `push2his`

```http
GET https://push2his.eastmoney.com/api/qt/stock/kline/get
    ?secid=0.000001          # 0.=深市 1.=沪市；指数 0.399006 / 1.000001；板块 90.BK0475
    &klt=101                 # 101=日线
    &fqt=2                   # 0=不复权 1=前复权 2=后复权
    &beg=20230101&end=20250630
    &fields1=f1,f2,f3,f4,f5,f6
    &fields2=f51,f52,f53,f54,f55,f56,f57,f58
    &lmt=10000
```

**返回格式**（注意：是逗号分隔**字符串**，不是 JSON 数组）：

```json
{"data": {"code": "000001", "name": "平安银行",
  "klines": ["2025-01-03,1744.98,1737.47,1757.48,1734.97,1154680,1320520977.59,1.29"]}}
```

字段顺序：`日期,开,收,高,低,成交量,成交额,振幅`

**代码**：`data/sources/em_quote.py::fetch_kline`

### 2.2 名称 / 总股本 / 行业 —— `push2`

```http
GET https://push2.eastmoney.com/api/qt/stock/get?secid=1.600519&fields=f57,f58,f84,f85,f127,f116
```

| 字段 | 含义 | 备注 |
|---|---|---|
| `f57` / `f58` | 代码 / 名称 | |
| `f84` / `f85` | 总股本 / 流通股 | 算总市值用 |
| `f116` | 总市值 | |
| **`f127`** | **所属行业** | ⚠️ **不是 `f100`**（单只接口里 `f100` 恒为 null）；返回如"白酒Ⅱ"，需去掉罗马数字后缀 |

`f128` = 地区板块，`f129` = 概念板块列表（逗号分隔）。

**代码**：`em_quote.py::fetch_meta`

### 2.3 公告列表 —— `np-anotice-stock`

```http
GET https://np-anotice-stock.eastmoney.com/api/security/ann
    ?sr=-1&page_size=100&page_index=1
    &ann_type=A              # A=沪深A股
    &client_source=web&f_node=0&s_node=0
    &stock_list=600519&begin_time=2023-01-01&end_time=2025-06-30
```

**返回**：`data.list[]` 含 `art_code`、`title`、`notice_date`、`codes[].stock_code`、`columns[]`。

⚠️ **两个坑**
1. **必须翻页**：`page_size` 上限 100，单只 2.5 年约 200-550 条 → 只取第 1 页会漏掉 2023 年（实测从 800 条漏成只有 100/只）
2. **`totle_hits` 不可靠**（常为 0）：判断翻页结束要用"本页未拿满"，不能用它

**能力边界**：可回溯到 2023 年（实测 000001 全年 2023 = 112 条；2023-01 全市场 31,632 条）。

**代码**：`em_notice.py::fetch_all`

### 2.4 公告正文 —— `np-cnotice-stock`

```http
GET https://np-cnotice-stock.eastmoney.com/api/content/ann
    ?art_code=AN202410261234567890&client_source=web&page_index=1
```

返回 `data.notice_content`，纯文本，实测 757~1320 字。

⚠️ **致命坑：IP 级限流**
连续请求约 **50 次**后开始 `RemoteDisconnected`（服务端直接断连接）。此时**连之前成功过的公告也取不到**，不是参数问题、也不是文档没有正文。

**实测限流规律（重要）**：

| 观察 | 数据 |
|---|---|
| 触发点 | 约 **第 57–60 次请求**开始连续拒绝 |
| 间隔 1.5s 时 | 第 58 篇被拒 |
| 间隔 3.0s 时 | 同样在 60 篇上下被拒（冷却未到期时第 1 篇就被拒） |
| 结论 | 是**每窗口配额（约 60 次）**，不是频率限制 —— **降速无用，只能分批 + 冷却** |

**因此的正确做法**：每批 **≤50 篇**，批间冷却 **30–60 分钟**。
不要指望一次跑完 2,816 篇，那会连续触发封禁。

**应对**（已在代码里）：
- 建库时正文抓取连续失败 5 次 → 自动降级为"只入库标题"，不拖垮整条管线
- 正文单独用 `scripts/fill_content.py` 分批补：可断点续传、连续失败 6 次自停
- **按类型优先级补**：`--doc-types 年报,季报,半年报,分红`（见下）

**为什么按类型优先**：8 只股票 2,816 条公告里，`其他` 占 92.2%（H股翌日披露、股权激励明细等），
对"小白看懂"价值很低；真正承担证据的是**财报与分红，共 219 条**：

| 类型 | 条数 | 价值 |
|---|---|---|
| 年报 | 108 | 高（营收/利润/风险提示） |
| 季报 | 59 | 高（增速变化） |
| 分红 | 52 | 中（现金回报） |
| 其他 | 2,597 | 低（可后补，甚至不补） |

补这 219 条只需 **5 批 × 50 篇**（含冷却约 4 小时挂机），就能覆盖最重要的证据。

**代码**：`em_notice.py::fetch_content`、`scripts/fill_content.py`

### 2.5 财务三表 —— `datacenter-web`

```http
GET https://datacenter-web.eastmoney.com/api/data/v1/get
    ?reportName=RPT_DMSK_FN_INCOME        # 利润表；资产负债表 RPT_DMSK_FN_BALANCE
    &columns=ALL
    &filter=(SECURITY_CODE="600519")
    &pageNumber=1&pageSize=20
    &sortColumns=REPORT_DATE&sortTypes=-1
    &source=WEB&client=WEB
```

**每个报告期一行，自带 `NOTICE_DATE`（实际披露日）**：

```json
{"REPORT_DATE": "2024-09-30 00:00:00", "NOTICE_DATE": "2024-10-19 00:00:00",
 "TOTAL_OPERATE_INCOME": 111582000000.0, "PARENT_NETPROFIT": 39729000000.0,
 "TOTAL_EQUITY": 490469000000.0, "TOTAL_ASSETS": 5745988000000.0,
 "DEBT_ASSET_RATIO": 91.46}
```

| 报表 | 字段 | 存成 |
|---|---|---|
| 利润表 | `TOTAL_OPERATE_INCOME` | `revenue` |
| 利润表 | `PARENT_NETPROFIT` | `net_profit` |
| 资产负债表 | `TOTAL_EQUITY` | `total_equity` |
| 资产负债表 | `TOTAL_ASSETS` | `total_assets` |
| 资产负债表 | `DEBT_ASSET_RATIO` | `debt_ratio`(%) |

⚠️ **两个坑**
1. **重述行**：同一报告期可能返回两行，重述行 `NOTICE_DATE` 更晚。用 `REPLACE` 会用"事后修订版"覆盖"当时披露版"，破坏点时间语义 → 改为**按披露日升序 + `INSERT OR IGNORE`（首次披露优先）**
2. **利润表的 `NOTICE_DATE` 不可靠**（同一期能比资产负债表晚一整年，导致 PE 算不出来）→ 统一**以资产负债表的 `NOTICE_DATE`** 作为该期披露日

**为什么不用 akshare**：akshare 只是这个接口的封装，直连少一层版本依赖（akshare 接口改名极频繁）。要换的话把 `fetch_financials` 内部换成 `ak.stock_financial_abstract`，返回结构已对齐。

**代码**：`em_finance.py`

### 2.6 新闻（近端）—— `np-listapi`

```http
GET https://np-listapi.eastmoney.com/comm/web/getNewsByColumns
    ?client=web&biz=web_news_col&column=345&order=1&needInteractData=0
    &page_index=1&page_size=20
    &req_trace=<毫秒时间戳>      # ⚠️ 少这个参数会返回空
```

返回 `data.list[]` 含 `showTime`、`title`、`summary`、`mediaName`、`uniqueUrl`；`totle_hits` 上限 5000。

**能力边界**：每页 20 条，最多约 250 页 ≈ **回退 40 天**。

⚠️ akshare 用的另一个接口（`search-api-web`）直连实测返回 0 条 —— 已弃用。

**代码**：`em_news.py`

### 2.7 板块 —— `push2` / `push2his`

```http
GET https://push2.eastmoney.com/api/qt/clist/get     # 板块列表
    ?pn=1&pz=100&po=1&np=1&fltt=2&invt=2&fid=f3
    &fs=m:90+t:2                                    # 行业板块（概念板块是 t:3）
    &fields=f12,f14,f3

GET https://push2.eastmoney.com/api/qt/clist/get     # 成分股
    ?fs=b:BK0475&fields=f12,f14

GET https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=90.BK0475   # 板块历史
```

⚠️ **三个坑**
1. **单页上限 100**：`pz=200` 也只会返回 100 条，而行业板块共约 **496 个** → 必须翻页 5 次，否则只拿到"当日涨幅前 100"（银行/白酒/保险都不在里面）
2. **选板逻辑**：先用 `f127` 行业名做**精确 → 前缀 → 包含**三档匹配，并排除「其他XX」；三档都不中才按涨跌幅绝对值兜底
3. **假阳性**：双向包含会让「电池」错配「燃料电池」

**代码**：`em_board.py`、`data/boards.py`

### 2.8 公告正文（巨潮 PDF）—— `cninfo`

东财正文接口（§2.4）有 **5,000 字截断 + 约 60 次/窗口封禁** 两个硬伤，所以财报类正文改走巨潮。

```http
POST http://www.cninfo.com.cn/new/hisAnnouncement/query
     form: stock=600519,gssh0600519   # orgId 见下
           pageNum=1&pageSize=30&tabName=fulltext&column=szse
           seDate=2024-01-01~2025-06-30
→ 返回 announcementTitle / adjunctUrl（PDF 路径）/ announcementTime

GET  http://static.cninfo.com.cn/finalpage/2025-04-03/1222993920.PDF   # 下载 PDF
```

**orgId 规则（实测，不是简单拼接）**：深市主板/沪市主板多为 `gssz0`/`gssh0`+code，
但不少股票是 `990000xxxx` 或 `GDxxxx`（美的 9900005965、宁德 GD165627）。
正确做法：拉官方列表 `szse_stock.json`（实测含全市场 6,267 条）建 code→orgId 缓存到 `data_files/cninfo_orgid.json`。

**处理链路**：`em_cninfo.fetch_list/fetch_pdf` → `pdf_text.extract_text/split_sections/to_chunks`
→ `data/chunks.save_fulltext`（存 doc_chunks 原文 + chunks_fts 分词）。

**实测质量**：茅台年报 143 页 176,089 字；章节切分跳过目录、保留「管理层讨论/重要事项/主要财务指标」、
丢「财务报告/公司治理/环境」；每块注入上下文前缀 + 页码。

**代码**：`data/sources/em_cninfo.py`、`data/pdf_text.py`、`scripts/fill_content_cninfo.py`

### 2.9 关于"公开接口"的性质（写进报告用）

这些是东财**网页前端自己用的内部 JSON 接口**。任何人打开 `quote.eastmoney.com` 按 F12 都能看到同样的请求。

- 无官方文档、无 SLA、无版本管理，**随时可能改**
- 有隐式风控：频率过高会 `RemoteDisconnected` 或 502（详见 §7）
- 合规边界：抓**公开可见**内容、**仅课程研究**、**不对外分发原始数据** → 可接受；公开发布快照或对外提供服务 → 超出边界

**七个接口的来源**：2 个来自 akshare 源码（公告列表、新闻搜索），4 个按东财命名规律推测后逐个实测通过，1 个（巨潮）来自官方披露平台公开列表。

## 三、存储：12 张表

**为什么是 SQLite 单文件**：本项目的核心约束是"只允许看到 `as_of` 之前已公开的信息"，用 SQL 的 `WHERE publish_time < ?` 表达它，比 Parquet 目录 + 文件命名约定可靠一个数量级；顺带还有 FTS5 自带 BM25、整文件可 sha256、零部署。

| 表 | 内容 | 主键 | 写入策略 | 现有行数 |
|---|---|---|---|---|
| `instruments` | 代码/名称/行业/总股本 | `code` | REPLACE | 8 |
| `prices_daily` | 日线，hfq 与 qfq 各一套 | `(code,date,adj)` | REPLACE | 9,616 |
| `index_daily` | 指数日线（顺带交易日历） | `(secid,date)` | REPLACE | 1,202 |
| `announcements` | 标题 + 正文 | `art_code` | **upsert，正文不覆盖** | 2,816 |
| `financials` | 财务长表（一行一指标） | `(code,report_period,item)` | **IGNORE（首次披露优先）** | 800 |
| `boards` | 板块列表（快照） | `board_code` | REPLACE | 8 |
| `board_daily` | 板块行情 | `(board_code,date)` | REPLACE | 4,808 |
| `board_members` | 板块成分（快照，会变） | `(board_code,code,snapshot_date)` | REPLACE | 340 |
| `news` | 近端新闻 | `url` | IGNORE | 0 |
| `docs_fts` | 标题级索引（FTS5 虚表） | — | 先清后插 | 2,873 |
| `doc_meta` | 公告正文元数据（公司/报告期/页数/sha256/解析状态） | `doc_id` | REPLACE | 281 |
| `doc_chunks` | 公告正文分块（原文，带页码/章节） | `(doc_id,seq)` | 先删后插 | 3,627 |
| `chunks_fts` | 分块索引（分词，检索用） | — | 先删后插 | 3,627 |
| `ingest_log` | 每次抓取的记账 | 自增 | append | — |

### 3.2 两张 FTS 表是干什么的（重要，别把虚拟表当普通表）

FTS5 **虚拟表不是"存数据"的表，是倒排索引**。你 `INSERT` 一段文本进去，它自动分词、
建倒排索引，之后 `MATCH` 查询走索引，毫秒级返回。**它里面存的是分词，不是原文。**

我们有两张，分工不同：

| 表 | 索引的内容 | 源表 | 谁写 | 谁读 | 用途 |
|---|---|---|---|---|---|
| `docs_fts` | 公告**标题** | `announcements` | `data/indexer.build_fts()` | `db.search_docs()` | 标题级预过滤（快，覆盖全部 2,816 条） |
| `chunks_fts` | 公告**正文分块** | `doc_chunks` | `data/chunks.save_fulltext()` | `chunks.search_chunks()` | 证据检索（精准，带页码/章节） |

**为什么两张，而不是合并成一张：**

1. **覆盖不同**：标题索引覆盖全部 2,816 条（包括没正文的 2,468 条"其他"）；正文索引只有 183 篇财报
2. **粒度不同**：`docs_fts` 一行 = 一篇公告（整篇一个 doc）；`chunks_fts` 一行 = 一个 ~800 字分块（带页码/章节）
3. **打分不可比**：整篇 vs 分块的 BM25 分数不在一个量级，混一张表检索质量会乱

**关键关系（原文 vs 分词）：**

```
announcements.content / doc_chunks.text   ← 原文（给人看、给 Evidence.quote 引用）
        ↓ tokenize()（jieba 预分词，unicode61 不切中文）
docs_fts.body / chunks_fts.text           ← 分词结果（给 MATCH 检索）
```

**所以你在数据库里看到的 FTS 相关表不是 2 张，是 12 张。** 每张 FTS 虚拟表背后有 5 张影子表：

| 影子表 | 行数（chunks_fts） | 行数（docs_fts） | 干什么的 |
|---|---|---|---|
| `chunks_fts` / `docs_fts` | 3,627 | 2,873 | 虚拟表本体（你 `MATCH` 的就是它） |
| `*_config` | 1 | 1 | FTS 配置（tokenizer 等元数据） |
| `*_content` | 3,627 | 2,873 | 你 INSERT 进去的原文副本（倒排前） |
| `*_data` | 2,479 | 235 | **倒排索引数据**（词 → 文档映射） |
| `*_idx` | 2,621 | 298 | 索引指针（指向 data 的偏移） |
| `*_docsize` | 3,627 | 2,873 | 每个文档的 token 数（**BM25 打分靠它**） |

全部展开是这 12 张：

```
chunks_fts            docs_fts
chunks_fts_config     docs_fts_config
chunks_fts_content    docs_fts_content
chunks_fts_data       docs_fts_data
chunks_fts_idx        docs_fts_idx
chunks_fts_docsize    docs_fts_docsize
```

**这些影子表是 FTS5 自动维护的**，你 `INSERT` 进 `chunks_fts` / `docs_fts` 时它们同步更新。
**不要手动改或删** —— 删了 `*_data` 检索就坏，删了 `*_docsize` BM25 打分就失效。
判断"数据冗余"时，请把它们当成检索引擎的内部实现，而不是业务表。

### 三条存储规则

**规则 1：每条记录都要有"两个时间"**

| 字段 | 含义 | 用途 |
|---|---|---|
| `publish_time` / `notice_date` / `announce_date` | **业务时间**（信息公开的时刻） | as-of 只认它 |
| `ingested_at` | 入库时间 | 排查数据新旧 |

`ingested_at` **绝不能**出现在 as-of 条件里 —— 用它等于偷看未来，而且**不会报错**。

**规则 2：时间精度不足时往"更保守"取整**

东财 `notice_date` 只到日，但公告可能当晚 23:50 才发。所以 `publish_time = notice_date + " 23:59:59"`，查询用严格小于 `< as_of 00:00:00` → **当天公告次日才可见**。

代价是损失当天信息，换来绝对不会偷看未来。

**规则 3：业务代码不许写裸 SQL，只走 `data/db.py`**

`as_of` 漏写就是前视偏差，而漏写不会报错。锁在函数里才能被单测覆盖。
现有 **10 个取数函数**（另有 `connect()` / `_bound()` 两个基础设施，共 12 个 def）：

```python
asof_docs(code, as_of, k)        # 公告，publish_time < as_of
asof_financials(code, as_of)     # 财务，announce_date < as_of
asof_valuation(code, as_of)      # 自算 PE/PB
series(code, start, end, adj)    # 日线，adj 必填
trade_dates(start, end)          # 交易日历
search_docs(query, as_of, k)     # 标题级 FTS 预过滤
search_chunks(query, as_of, k)  # 正文分块检索（证据检索唯一入口，带页码）
read_pages(doc_id, from, to)     # 读指定页码范围原文
news_since(since, keyword, k)    # 近端新闻（历史决策点禁用）
board_pct_changes(as_of, k)      # 板块当日涨跌幅
asof_industry(code)              # 标的所属行业
last_ingest(dataset)             # 该数据集最后抓取时间（TTL 用）
```

## 四、检索：FTS5 + jieba

FTS5 默认 `unicode61` 按空白切分，中文没空格 → 整句变成一个 token，检索失效。

**实测对照（重要）**：

| 查询 | `trigram` | jieba 预分词 |
|---|---|---|
| `营业收入` | ✅ 命中 2 条 | ✅ |
| `关联交易` | ✅ 命中 1 条 | ✅ |
| `净利润同比` | ❌ **命中 0 条** | ✅ |

原因：原文是"净利润 464 亿，同比 增长"，`trigram` 只能匹配连续字符串，跨词组合全失效。而 agent 的检索请求几乎都是多词 → **必须 jieba 预分词**，不能图省事用 trigram。

**实现**：`data/text.py::tokenize`（jieba 缺失时降级 2-gram）；`docs_fts.body` 存标题分词（预过滤用）。

**正文检索已独立**：`chunks_fts` 存正文分块的分词（检索用），`doc_chunks.text` 存原文（引用用）。
`search_chunks` 返回 doc_id/页码/章节 + 原文片段；`read_pages` 读整页。两者都带 as_of 约束。

## 八、踩过的坑（全部有代码注释）

| # | 坑 | 后果 | 修法 |
|---|---|---|---|
| 1 | `INSERT OR REPLACE` 写公告 | 重跑 `--no-content` **把已抓的 38 条正文冲成空串** | `ON CONFLICT DO UPDATE` + `CASE WHEN excluded.content_len>0` |
| 2 | 公告列表只取第 1 页 | 每只仅 100 条，**2023 年公告全漏**（800 → 2,816） | `fetch_all` 翻页，用"本页未满"判结束 |
| 3 | 财务用 REPLACE | 重述行覆盖原始披露，破坏点时间语义 | 升序写入 + `INSERT OR IGNORE` |
| 4 | 利润表 `NOTICE_DATE` | 同一期能差一整年 → PE 算不出来 | 统一用资产负债表的披露日 |
| 5 | 行业取 `f100` | 单只接口恒为 null → 行业全空 → 板块选错 | 改 `f127`，去掉「Ⅱ」后缀 |
| 6 | 板块 `pz=200` | 接口单页上限 100，只拿到涨跌榜前 100 | 翻页取全 ~496 个 |
| 7 | 板块名双向包含 | 「电池」误配「燃料电池」 | 精确 → 前缀 → 包含三档，排除「其他XX」 |
| 8 | 正文接口高频请求 | IP 限流，连成功过的也取不到 | 降级只存标题 + 单独分批补 |
| 9 | 用 `hfq` 显示价格 | 平安银行 hfq=1737 而真实价 12 元 | 展示用 `qfq`，算收益两者等价 |

**hfq / qfq 实测结论**：两条序列在两次不同截止日拉取时完全一致（最大差异 0.0000 元）。所以
- 只用**收益率** → 两者数学等价
- 涉及**价格水平**（"跌到 50 元"、阈值判断）→ 用 **hfq**（历史值恒定）
- 真正要防的是**混用数据源**（新浪/东财/同花顺复权口径不同）

## 十一、必须写进报告的数据限制

1. **新闻不可回溯**（实测：只能最新 10~40 天，且接口不稳定）→ 证据以公告为主，新闻仅近端；**新闻不进历史证据链**（否则是前视偏差）
2. **拿不到全市场涨跌家数**（无历史序列）→ 只能用"指数跌幅 + 板块跌幅 + 自选池内几只下跌"，文案**不得写具体家数**
3. **总股本用当前值近似**（它随增发/回购变化）→ 报告里声明
4. **板块成分用当前快照近似**（板块分类会调整）→ 报告里声明，且 `board_members` 带 `snapshot_date`
5. **公告正文来自巨潮 PDF 解析**：只保留定性章节（管理层讨论/重要事项），财务报表附注不入库；扫描件（无文字层）只用标题

## 十二、每个数据集的校验规则

| 数据集 | 必须校验 |
|---|---|
| 日线 | 时间连续（与交易日历对齐）｜无重复日期｜无负价｜hfq/qfq 的**收益率**一致 |
| 指数 | 覆盖全区间，缺一天即报警 |
| 公告列表 | `notice_date` ≤ 截止日｜`art_code` 唯一｜标题非空｜**条数 ≥ 每页上限则说明没翻完页** |
| 公告正文 | 巨潮：`parse_status` 标记 ok/scanned/no_match｜正文里"证券代码"与 `stock_code` 一致（防串号）｜`doc_meta.pdf_sha256` 可复算 |
| 财务 | `announce_date`（不是 `report_period`）< 决策日｜单位统一为元｜缺失保留 NULL 不填 0 |
| 板块 | 板块名与 `f127` 行业能匹配上｜非「其他XX」兜底板 |
| 新闻 | 返回空**记 warning 不重试**（接口本身不稳） |
| 全部 | 写 `ingest_log` + manifest（行数、时间范围、sha256） |
